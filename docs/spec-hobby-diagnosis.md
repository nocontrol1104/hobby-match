# 趣味診断 仕様書（v0.2 案）の要点

原本（Claude Doc）: https://claude.ai/artifact/6BEdczoHG1GPgHiSSuvjGR （2026-11-18 作成）
ここは開発用の要約です。仕様を変えたら原本とこのファイルの両方を更新してください。

実装は `site/`（`data.js` と `app.js`）にあります。

## 概要とゴール

- 14問・約2分の診断で、その人に合う趣味を3つ提案する。
- 結果の「始め方」からアフィリエイトリンクで収益化する。
- 結果を保存し、将来「同じ趣味の人とつながる」機能の入口にする。
- 対象: 新しい趣味を探している20〜40代の社会人。
- KPI（仮）: 診断完了率 70%以上、結果ページのリンククリック率、SNSシェア率。将来は会員登録率。

## 質問（12問は5段階、2問は条件）

回答「とてもそう思う」〜「まったくそう思わない」を +2〜−2 に変換。「向き」は +2 のとき軸が動く側。

| No | 質問文（仮） | 軸 | 向き |
|---|---|---|---|
| 1 | 休日は家でゆっくり過ごしたい | 場所 | 屋内 |
| 2 | 天気のいい日は外に出たくなる | 場所 | 屋外 |
| 3 | 自然の中にいると落ち着く | 場所 | 屋外 |
| 4 | ひとりで黙々と集中する時間が好き | 人数 | ひとり |
| 5 | 初対面の人ともすぐ打ち解けられる | 人数 | みんな |
| 6 | 楽しさを誰かと分かち合いたい | 人数 | みんな |
| 7 | 体を動かすとすっきりする | 活動量 | アクティブ |
| 8 | 細かい作業を長時間続けられる | 活動量 | じっくり |
| 9 | 何かを作り上げることに喜びを感じる | 創作 | つくる |
| 10 | 見る・味わう・体験することが好き | 創作 | 楽しむ |
| 11 | 始めるなら道具にもこだわりたい | 本気度 | 本格的 |
| 12 | まずはお金をかけずに試したい | 本気度 | 気軽 |
| 13 | 趣味に使える予算は月いくら？（〜3,000円 / 〜1万円 / 〜3万円 / それ以上） | 条件 | 絞り込み |
| 14 | 趣味に使える時間は週どれくらい？（〜1時間 / 〜3時間 / 〜半日 / それ以上） | 条件 | 絞り込み |

1画面1問、進捗バーあり、戻るボタンで回答を直せる。

## 診断ロジック

1. 各回答を +2〜−2 に変換し、「向き」が 0 側の質問は符号を反転する。
2. 軸ごとに合計して 0〜100 に正規化する: `s_a = (Σr_i + 2n) / 4n × 100`
3. 上3軸でタイプを決める。ちょうど 50 のときはその軸の「+2 側」の質問の回答で決める。
4. 予算・時間を超える趣味を候補から外す。外すと3カテゴリ未満になるなら外さず減点にする。減点は「条件を超えた段階数（予算と時間の合計）× 3」、上限 15。例: 週〜1時間と答えた人に週2〜3時間の趣味は −3、週4〜5時間なら −6。
5. 合い度を計算する: `fit(u,h) = 100 × (1 − √(Σ w_a (u_a − h_a)²) / (100 √Σw_a))`
6. 合い度順、同じカテゴリは1件までで上位3件。

- 重みの初期値: 場所・人数・活動量 1.0、創作 0.8、本気度 0.6。
- 将来の「意外な出会い」枠: 4位以降から上3軸のうち1軸だけ逆の趣味を1件混ぜる。
- 当たり方は趣味マスタの軸の値でほぼ決まる。初期30〜50件は手で付け、公開後はクリック率で調整。
- 計算はブラウザだけで完結させる。

## 結果画面

上から順に:

1. 動物キャラクターのイラスト・タイプ名・一言説明、X / LINE シェア（タイプ別OGP画像）
2. 5軸レーダーチャート
3. おすすめ趣味3件（合い度、合う理由、初期費用・月額・週の時間の目安）
4. 各趣味の「始め方3ステップ」にアフィリエイトリンク（知る: 入門書・講座 / 試す: 体験レッスン・レンタル / そろえる: 入門セット）
5. 「同じタイプの人とつながる（準備中）」と Google フォーム（無料）でのメール登録
6. 「もう一度診断する」「他のタイプを見る」

- リンクには必ず「PR」表記（2023年10月からのステマ規制）。
- どの結果のどのリンクが押されたか（趣味ID・ステップ・順位）を記録する。

## データ設計

診断結果は匿名ID付きで残し（MVP はブラウザ内と URL、段階3から DB）、会員登録時にユーザーに紐付ける。

| テーブル | 主な項目 | 時期 |
|---|---|---|
| hobbies | id, 名前, カテゴリ, 5軸の値, 初期費用, 月額, 週の時間, 説明, 始め方3ステップ | MVP（ファイル） |
| hobby_links | hobby_id, ステップ, 表示名, URL, 提携先, 有効フラグ | MVP（ファイル） |
| questions | id, 文面, 軸, 向き, 表示順, 版 | MVP（ファイル） |
| types | id, 動物, タイプ名, 説明, イラスト, OGP画像 | MVP（ファイル） |
| diagnoses | id, 匿名ID, user_id, 回答, 5軸スコア, タイプ, おすすめ上位, 質問の版, 日時 | MVP はブラウザ内と URL、段階3で DB |
| link_clicks | diagnosis_id, hobby_id, link_id, 順位, 日時 | MVP は GA4 イベント、段階3で DB |
| users | id, ニックネーム, 地域（都道府県・市区町村）, 年代, 公開設定 | 段階3 |
| user_hobbies | user_id, hobby_id, 状態（興味あり/始めた/続けている） | 段階3 |
| groups / connections / messages | 趣味別グループ, 申請, 承認, ブロック, 通報, メッセージ | 段階3 |
| events | 主催者, 趣味, 地域, 開催日時, 場所, 定員, 参加者, 本人確認済みか | 段階4 |

- MVP は DB を持たない。マスタ類はファイル、診断結果は URL に入れて共有し、診断完了とリンククリックは GA4（無料）で計測する。
- 質問を変えても比較できるよう、診断に質問の版を記録する。
- 交流機能には年齢確認、通報・ブロック、利用規約・プライバシーポリシーが必要。異性紹介と誤解されない設計にする。

## MVP範囲と段階

画面: トップ → 質問（14問） → 結果（URLで開き直せる） → 趣味詳細（記事兼用） → タイプ一覧。

| 段階 | 内容 | 完了の目安 |
|---|---|---|
| 1. MVP | 上の5画面、趣味マスタ30〜50件、動物キャラ8種、リンク、GA4計測、OGP画像 | 診断完了率とクリック率が取れる |
| 2. 集客 | 趣味詳細の記事化（SEO）、趣味マスタ100件、事前メール登録 | 検索とSNSから流入がある |
| 3. オンライン交流 | 会員登録、マイ趣味、同じ趣味・近い地域の人一覧、趣味別グループ、通報・ブロック | 登録者同士のやり取りが生まれる |
| 4. オフ会・地域の集まり | イベント作成と参加申込、地域で探す、本人確認、主催者向けルール | 月に数件の集まりが開かれる |

技術は無料で運用できる構成にする。

- 段階1〜2: 静的サイトを GitHub Pages で公開。診断の計算はすべてブラウザで行う。
- 段階3〜4: 会員・グループ・イベントのデータを Supabase の無料枠に置く。サイトは GitHub Pages のまま。
- 無料枠の上限に近づいたら、その時点で有料化か移行を判断する（費用が出る判断はユーザーの承認が必要）。
