## 1. 目的

- 人と趣味をつなぎ、**新しい趣味に出会える**サイトを作って運用する。
- まず「趣味診断」で、その人に合う新しい趣味を3つ提案する。
- ゆくゆくは、**同じ趣味の人同士がつながれる**機能を加える（恋活ではなく趣味仲間）。
- 収益はアフィリエイト。柱は**習い事・スクールの無料体験の申込**（1件あたり 1,000〜17,500円）。Amazon・楽天の物販（料率 2〜4% 中心）は補助。
- 差別化: 「診断 → 体験 → 趣味仲間」を一気通貫で提供する国内サービスは、調査した範囲では見当たらなかった。

## 4. 画面

ハッシュでページを切り替える1ページ構成です（`site/app.js`）。

| 画面 | URL | 内容 |
|---|---|---|
| トップ | `#`（空） | 診断を始める、前回の結果を見る、タイプ一覧へ |
| 質問 | `#q` | 1画面1問、進捗バー、戻るボタン、やめるボタン |
| 結果 | `#r=<版>.<回答>` | 動物タイプ・説明、X / LINE シェアと URL コピー、5軸レーダーチャート、おすすめ3件（合い度・合う理由・費用と時間の目安・始め方3ステップ）、意外な出会い1件、事前登録、もう一度診断、タイプ一覧 |
| タイプ一覧 | `#types` | 8タイプの紹介 |
| 趣味詳細 | `#hobby=<趣味ID>` | 趣味の説明、費用・時間の目安、始め方3ステップ（段階2で記事化する） |

全ページ共通: ファーストビューに「本ページはプロモーションが含まれています」、アフィリエイトリンクの近くに「PR」、リンクに `rel="sponsored"`。

## 5. 使う技術

| 項目 | 内容 |
|---|---|
| サイト | 静的 HTML / CSS / JavaScript（ビルドなし、外部ライブラリなし、Google Fonts のみ） |
| データ | `site/data.js` に質問・タイプ・趣味マスタ・リンクを持つ（`file://` でも動くよう JSON ではなく JS） |
| ロジック | `site/app.js`。診断エンジンは純粋関数で `window.ShumiEngine` から検証できる |
| 設定 | `site/config.js`（サイト名、GA4 測定ID、事前登録・お問い合わせフォーム URL。秘密情報は書かない） |
| ホスティング | GitHub Pages（無料）。`.github/workflows/pages.yml` は今は手動実行のみ |
| 計測 | Google Analytics 4（無料） |
| 保存 | MVP は DB なし。診断結果は URL とブラウザの localStorage（匿名ID付き） |
| 将来の DB | 段階3から Supabase の無料枠。サイトは GitHub Pages のまま |

- 当初案の Next.js + Vercel は、無料で運用する方針から v0.2 で静的サイト + GitHub Pages に変えました。
- 無料枠の上限に近づいたら、その時点で有料化か移行を判断します（承認が必要）。

### 手元で動かす

```bash

python3 -m http.server 8000 --directory site   # http://localhost:8000/
# main のままなら古い試作
python3 -m http.server 8000 --directory prototype
```

## 8. 守ること

`CLAUDE.md` に全部書いてあります。特に大事なもの:

- **費用が発生する作業は必ず手を止めてオーナーの承認を得る**（有料プラン、ドメイン購入、有料 API、有料素材、広告出稿など）。
- `main` に直接コミットしない。作業ブランチ → PR。1 PR は1つの目的。仕様を変えたら `docs/` も同じ PR で更新する。
- ドキュメント、コミットメッセージ本文、PR の説明は日本語。
- **報酬の高い趣味を診断結果で優先しない。** 診断の順位とアフィリエイトの並べ方は別のロジックにする。
- 質問を変えたら質問の版（`questionVersion`）を上げる。
- アフィリエイトのあるページはファーストビューに「本ページはプロモーションが含まれています」、リンクの近くに「PR」。
- Amazon は有料 SNS 広告経由の購入が対象外（2026-04-20 改定）。広告施策は ASP 案件側へ誘導する。
- 秘密情報（API キー、ASP の ID、パスワード）と `.env` はコミットしない。ユーザー入力を HTML に出すときは必ずエスケープする。
- 診断結果は匿名IDで扱い、個人情報を不要に集めない。
